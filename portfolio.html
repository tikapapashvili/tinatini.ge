Case study 02

Payment API Refund Functionality

To protect privacy and security, this project has been modified and sensitive information is not displayed.

Role: Business Analyst

Overview: Designed a secure, reliable and user-friendly refund capability for an existing payment platform. The solution enables authorized merchants to initiate full and partial refunds through REST APIs while maintaining transaction integrity, accurate statuses, auditability and operational control.

The analysis covered the complete lifecycle—from authentication and eligibility validation to provider processing, webhook notifications and financial reconciliation—with special attention to idempotency, duplicate prevention, concurrent partial refunds, timeouts, asynchronous processing and failure recovery.

Key deliverables
  • AS-IS and TO-BE process analysis
  • Project scope and feasibility assessment
  • Stakeholder analysis and RACI matrix
  • Functional and non-functional requirements
  • Business rules and refund eligibility criteria
  • User stories with Gherkin acceptance criteria
  • BPMN and UML use case diagrams
Technical & delivery analysis
  • REST API requirements and error catalogue
  • Refund status and data requirements
  • Detailed use cases
  • Risk assessment and mitigation strategy
  • Requirements traceability matrix
  • Test scenario recommendations
  • MVP definition and phased roadmap
